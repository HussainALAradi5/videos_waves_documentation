Every service below has a free plan. Each needs an account that you create and sign in to yourself; keys and passwords are entered only in each provider's dashboard and are never committed.

Notes from the first deploy:
- The build command is `npm ci --include=dev && npm run build`: with `NODE_ENV=production`, plain `npm ci` skips the pinned TypeScript and the build falls back to a newer global one that rejects the config.
- Vercel's GitHub app needs access to `videos_waves_client` (GitHub → Settings → Applications → Vercel → Configure), even though the repository is public.

## Order

1. **Atlas:** create a free M0 cluster, a database user, and allow network access from anywhere (`0.0.0.0/0`, since Render's free plan has no fixed IP). Copy the connection string and add the database name: `…mongodb.net/videos_waves?retryWrites=true&w=majority`.
2. **ImageKit:** create an account. From Developer options, copy the public key, private key, and URL endpoint.
3. **Render:** New → Blueprint → pick `videos_waves_server`. Enter the values marked `sync: false`:

   | Variable | Value |
   | --- | --- |
   | `MONGO_URI` | The Atlas string from step 1 |
   | `CORS_ORIGINS` | `https://<project>.vercel.app,https://hussainalaradi5.github.io` (add after step 4 if the name is not known yet) |
   | `PUBLIC_BASE_URL` | The Render address, for example `https://videos-waves-api.onrender.com` |
   | `IMAGEKIT_PUBLIC_KEY`, `IMAGEKIT_PRIVATE_KEY`, `IMAGEKIT_URL_ENDPOINT` | From step 2 |
   | `SEED_ADMIN_PASSWORD`, `SEED_USER_PASSWORD` | The passwords you will publish for the demo accounts (8+ characters with upper, lower, and a digit) |

   The JWT secrets are generated by Render. Each start runs `migrate:prod`, then `seed:prod`, then the API. Check `https://<api>/health`.
4. **Vercel:** Add New → Project → import `videos_waves_client`. Set `NEXT_PUBLIC_API_BASE_URL` to the Render address and deploy. Put the Vercel address into Render's `CORS_ORIGINS`.
5. **GitHub Pages (mobile):** in `videos_waves_mobile` → Settings → Pages, set Source to **GitHub Actions**. In Settings → Secrets and variables → Actions → Variables, add `API_BASE_URL` = the Render address. Push to `main` (or run the workflow by hand). The web demo appears at the Pages address, and the APK is attached to the workflow run as `videos-waves-apk`.

## Demo accounts

`seed:prod` runs on every start and is idempotent. It creates these accounts once, with a profile, follows, comments with Owner-badge replies, a direct chat, a group chat with a reaction, and one message request:

| Account | Role | Password |
| --- | --- | --- |
| `admin` (`admin@videos-waves.test`) | admin | `SEED_ADMIN_PASSWORD` |
| `moderator` (`moderator@videos-waves.test`) | admin | `SEED_ADMIN_PASSWORD` |
| `viewer`, `lina`, `omar`, `maya` (`<name>@videos-waves.test`) | user | `SEED_USER_PASSWORD` |

Because the passwords are public, visitors can change them or deactivate an account. Every start (each deploy, and each wake-up of a sleeping free instance) **resets** a changed demo password, signs out the devices that used it, and reactivates a deactivated demo account. Demo videos are public sample clips linked from their hosts, so seeding uploads nothing.

Seeding is refused in production unless `ALLOW_DEMO_SEED=true` (set by the Blueprint) and both passwords are set.
